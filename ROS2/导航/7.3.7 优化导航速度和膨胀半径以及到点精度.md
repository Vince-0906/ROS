# 导航速度控制
## 参数解读
### 1. Goal Checker 参数 (`general_goal_checker`)
用于定义机器人导航到达目标点时的判定标准与逻辑。

| **参数名**                  | **类型 / 默认值**                           | **参数含义与作用**                                                                              |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| **`stateful`**           | `True`                                 | **状态保持开关**。设为 `True` 时，只要机器人曾经满足过到达容差范围，即便后续由于习惯性漂移导致位置微幅偏离，也依然保持“已到达”状态，防止机器人在终点来回反复调整。 |
| **`plugin`**             | `"nav2_controller::SimpleGoalChecker"` | **目标判断插件类型**。`SimpleGoalChecker` 是最常用的简单判定插件，通过设定平面的位置和角度误差阈值来判断。                        |
| **`xy_goal_tolerance`**  | `0.25`                                 | **位置容差**（单位：米）。机器人与目标点在二维平面 $(x, y)$ 的欧氏距离小于 **0.25m** 即判定为位置达标。                         |
| **`yaw_goal_tolerance`** | `0.25`                                 | **角度/朝向容差**（单位：弧度）。机器人到达终点时的偏航角与目标朝向误差小于 **0.25 rad**（约 **14.3°**）即判定为角度达标。              |

### 2. MPPI 控制器核心参数 (`FollowPath`)

基于模型预测路径积分（MPPI）算法实现的局部路径规划器参数，通过蒙特卡洛大量随机采样预测轨迹并计算最优控制量。

#### 预测时域与采样配置

|**参数名**|**示例值**|**参数含义与作用**|
|---|---|---|
|**`plugin`**|`"nav2_mppi_controller::MPPIController"`|使用 Nav2 的 MPPI 控制器插件。|
|**`time_steps`**|`56`|**预测步数**。控制器向前预测轨迹的离散时间点数量。|
|**`model_dt`**|`0.05`|**时间步长**（单位：秒）。单步预测的时间间隔。总预测时长为 $56 \times 0.05 = 2.8$ 秒。|
|**`batch_size`**|`2000`|**轨迹采样批次大小**。每个控制周期内生成的候选随机轨迹数量（数量越多探索越充分，但消耗更多算力/GPU）。|
|**`iteration_count`**|`1`|**单周期优化迭代次数**。每个控制周期内对采样轨迹进行权重优化的轮数。|
|**`regenerate_noises`**|`true`|**噪声重新生成**。设为 `true` 表示每轮控制都生成新的高斯噪声；设为 `false` 则复用之前生成的随机数。|

#### 动态与加速度约束

|**参数名**|**示例值**|**参数含义与作用**|
|---|---|---|
|**`ax_max` / `ax_min`**|`3.0` / `-3.0`|$x$ 轴（前后方向）的最大加速度与最大减速度（单位：$\text{m/s}^2$）。|
|**`ay_max` / `ay_min`**|`3.0` / `-3.0`|$y$ 轴（侧向）的最大加速度与最大减速度（单位：$\text{m/s}^2$）。对差速/阿克曼模型不生效，对全向轮生效。|
|**`az_max`**|`3.5`|$z$ 轴（旋转）的最大角加速度（单位：$\text{rad/s}^2$）。|

#### 速度限制与采样标准差（Noise Std）

|**参数名**|**示例值**|**参数含义与作用**|
|---|---|---|
|**`vx_max` / `vx_min`**|`0.5` / `-0.35`|正向最大线速度为 **0.5 m/s**，最大倒车速度为 **-0.35 m/s**。|
|**`vy_max`**|`0.5`|最大侧向平移速度（单位：$\text{m/s}$，全向模型有效）。|
|**`wz_max`**|`1.9`|最大旋转角速度（单位：$\text{rad/s}$，约 **108.8°/s**）。|
|**`vx_std`**|`0.2`|采样线速度 $v_x$ 时注入的高斯噪声标准差，控制前后速度变化的探索幅度。|
|**`vy_std`**|`0.2`|采样侧向速度 $v_y$ 时注入的高斯噪声标准差。|
|**`wz_std`**|`0.4`|采样角速度 $\omega_z$ 时注入的高斯噪声标准差，控制转向探索的剧烈程度。|

#### 算法数学与运行逻辑

|**参数名**|**示例值**|**参数含义与作用**|
|---|---|---|
|**`temperature`**|`0.3`|**Softmax 温度系数** ($\lambda$)。控制轨迹权重的分布：数值越小，权重越集中在低代价的极优轨迹上；数值越大，对其他稍劣轨迹的容忍度越高。|
|**`gamma`**|`0.015`|**运动平滑/代价权衡因子**。用于平滑速度控制指令，防止控制量剧烈跳变。|
|**`motion_model`**|`"DiffDrive"`|**运动学模型**。可选 `DiffDrive`（两轮差速）、`Omni`（全向）或 `Ackermann`（阿克曼转向）。|
|**`prune_distance`**|`1.7`|**全局路径裁剪距离**（单位：米）。裁掉小车后方超过 **1.7m** 的旧全局路径点，节约计算资源。|
|**`transform_tolerance`**|`0.1`|**TF 转换容差**（单位：秒）。获取坐标系转换（TF）时允许的最大时间延迟。|
|**`visualize`**|`true`|**可视化开关**。是否将生成的候选轨迹群和最佳计算轨迹发布到话题中以供 RViz 渲染。|

### 3. 子配置块

#### `TrajectoryVisualizer`（轨迹可视化调节）

控制 RViz 中采样轨迹的渲染密度，防止因为同时画 2000 条轨迹导致图形界面卡顿：

- **`trajectory_step: 5`**：轨迹批次降采样步长。每 **5** 条采样轨迹中只选择 1 条进行画线绘制。
    
- **`time_step: 3`**：时间步长降采样。沿预测时域的每 **3** 个时间步绘制一个数据点。

#### `AckermannConstraints`（阿克曼转向约束）

- **`min_turning_r: 0.2`**：**最小转弯半径**（单位：米）。如果运动模型受限（或阿克曼模式），限制车辆最小转弯半径不得小于 **0.2m**。
## 具体参考代码nav2_params.yaml
```yaml
    general_goal_checker:
      stateful: True
      plugin: "nav2_controller::SimpleGoalChecker"
      xy_goal_tolerance: 0.25
      yaw_goal_tolerance: 0.25
    FollowPath:
      plugin: "nav2_mppi_controller::MPPIController"
      time_steps: 56
      model_dt: 0.05
      batch_size: 2000
      ax_max: 3.0
      ax_min: -3.0
      ay_max: 3.0
      ay_min: -3.0
      az_max: 3.5
      vx_std: 0.2
      vy_std: 0.2
      wz_std: 0.4
      vx_max: 0.5
      vx_min: -0.35
      vy_max: 0.5
      wz_max: 1.9
      iteration_count: 1
      prune_distance: 1.7
      transform_tolerance: 0.1
      temperature: 0.3
      gamma: 0.015
      motion_model: "DiffDrive"
      visualize: true
      regenerate_noises: true
      TrajectoryVisualizer:
        trajectory_step: 5
        time_step: 3
      AckermannConstraints:
        min_turning_r: 0.2
```
